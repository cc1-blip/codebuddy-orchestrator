# CodeBuddy 提示词实战模板指南

本文档提供 3 套针对不同工程阶段的即拷即用提示词模版。

---

## 模式 A：单点极速开发 / Bug 修复 (同步模式 · < 4 分钟)

适用于单文件修改、局部函数重构、语法修复等。

```markdown
请在当前工程完成以下单点修复。你负责实施与自测，直接修改并完成定向验证。

【任务目标】
1. 修复 [具体文件/函数/问题描述]
2. 补足对应定向单测，确保测试通过

【执行约束】
- 权限全放行，不要询问确认
- 优先保持既有代码风格与类型严谨
- 完成后给出简要修改说明与测试结果
```

---

## 模式 B：纵向闭环重型实施 (异步模式 · 10 ~ 90 分钟)

适用于跨文件纵向闭环（Vertical Slice）、复杂重构或全功能实施。

```markdown
实施当前任务 [任务编号与名称]。你是实施 Agent，只负责编码与自测，不得自审、不得自标 accepted、不得创建子代理。

【输入依据】
必须先完整读取并遵守根目录 AGENTS.md 以及任务书：[任务书路径]。

【工作区守则与边界 (严禁越界)】
1. 当前工作区可能有其他人员的未提交改动：绝不 reset、clean、checkout、覆盖 Allowed paths 之外的文件。
2. 严格受限于 Allowed paths：[允许修改的文件列表]。
3. 不得提交、推送、部署，不得随意改动 package.json/lockfile 新增运行时依赖。

【实施与测试要求】
1. 完整实现任务书全部验收标准与必测反例，不要只报告计划。
2. 运行任务书要求的全部聚焦测试与必要自测（长耗时测试日志落盘至 .codex-logs/，失败只看切片）。
3. 严格遵循无 any、无类型抑制、无 .skip/.only。

【交付格式】
完成后请以结构化 ready_for_review 格式交付：
- files_changed
- commands_run
- tests_added
- known_risks
- review_focus
- 并在末尾保留 CodeBuddy 性能消耗看板卡片。
```

---

## 模式 C：独立只读代码审查 (Code Review · 只读)

适用于主 Agent 或审查子 Agent 对工人交付的代码进行独立第三方交叉验收。

```markdown
对任务 [任务编号] 的最新提交进行独立代码审查。你不是最终决定者，只做只读独立分析，绝对不要修改任何文件，不要运行全量测试。

【审查重点】
1. 契约符合度：核对是否严格满足任务书中的验收标准与边界条件。
2. 安全与隔离：检查敏感字段是否泄露、超时控制是否完备、并发隔离是否到位。
3. 真实性检查：核实新增测试是否真正覆盖了核心逻辑，是否存在伪测试或过度断言。

【输出要求】
按严重级别（Critical / High / Medium / Low）列出具体文件与行号。
若无可挑剔的问题，请明确声明 "no findings"，由总控决定是否 accepted。
```
